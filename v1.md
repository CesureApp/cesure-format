# .cesure format — version 1 (frozen)

The specification of `.cesure` **version 1**, kept as it was when version 2 replaced it. Readers
keep reading v1 files forever; nothing writes them any more. The current version is described in
[README.md](README.md).

## What it is

`.cesure` is a UTF-8 JSON file for guitar tablature. It is:

- **Lossless** — a score saved as `.cesure` re-opens identically, every time
- **Human-readable** — plain JSON, no binary encoding, no compression
- **Versioned** — an explicit `version` field with a defined migration policy
- **Simple** — no external tooling, any JSON parser is enough to read it

## Why not MusicXML, MIDI, or AlphaTex?

| Format | Human-readable | Guitar-specific | Round-trip lossless | Versioned |
|---|---|---|---|---|
| `.cesure` | ✓ | ✓ | ✓ | ✓ |
| MusicXML | ✓ | ✗ | ~ | ✗ |
| AlphaTex | ✓ | ✓ | ~ | ✗ |
| MIDI | ✗ | ✗ | ✗ | ✗ |
| GP5 | ✗ | ✓ | ~ | ✗ |

## File structure

```
score.cesure
└── (UTF-8 JSON)
    ├── version   integer
    └── score     Score
```

### Root

| Field | Type | Required | Description |
|---|---|---|---|
| `version` | `integer` | ✓ | Format version. Current: `1`. |
| `score` | [`Score`](#score) | ✓ | The musical score. |

---

### Score

| Field | Type | Default | Description |
|---|---|---|---|
| `title` | `string` | `"Untitled"` | Song title. |
| `artist` | `string` | `""` | Artist name. |
| `album` | `string` | `""` | Album name. |
| `tempo` | `integer` | `120` | Initial tempo in BPM — in force until the first `tempoChanges` entry. |
| `tracks` | [`Track[]`](#track) | `[]` | Instrument tracks. |
| `tempoChanges` | [`TempoChange[]`](#tempochange) | `[]` | Mid-song tempo changes. Empty = constant tempo. |
| `license` | `string` | `""` | License of the published work (e.g. `Public Domain`, `CC BY 4.0`). Empty = the file says nothing — the case of every user-authored score. |
| `attribution` | `string` | `""` | Attribution of the edition — year and source URL included when applicable. It travels **with the file** because CC-BY legally requires it when a copy is kept. Empty = nothing to attribute. |

---

### TempoChange

A tempo change taking effect at the **start** of a measure and holding until the next one.

| Field | Type | Required | Description |
|---|---|---|---|
| `measureIndex` | `integer` | ✓ | 0-indexed measure at which the new tempo starts. |
| `tempo` | `integer` | ✓ | Tempo in BPM from that measure on. |

Tempo belongs to the **score**, not to a track: every track shares it, which is also how MIDI
models it (a single tempo track). The granularity is the measure — that of a tempo mark in
notation. A reader resolves the tempo at measure *m* as the last change whose `measureIndex` is
≤ *m*, falling back to `tempo`. The list needs no particular order; entries with a `measureIndex`
past the end of the score, or a non-positive `tempo`, are ignored.

---

### Track

| Field | Type | Default | Description |
|---|---|---|---|
| `name` | `string` | `"Guitar"` | Track / instrument name. |
| `tuning` | [`Note[]`](#note) | standard tuning | String tuning, from string 1 (highest) to string N (lowest). Standard 6-string: `[E4, B3, G3, D3, A2, E2]`. |
| `measures` | [`Measure[]`](#measure) | `[]` | Ordered list of measures. |
| `capo` | `integer` | `0` | Capo position in frets (0 = none). Tab numbers stay relative to the capo; only the sounding pitch shifts up. |
| `volume` | `number` | `1` | Track volume in the mix, `0`..`1`. Arrangement data, like `capo`: imported, saved, exported. |
| `instrument` | `string` \| `null` | `null` | Timbre: `GUITAR`, `BASS` or `PIANO`. Deliberately narrow — it lists only what a player can actually render. Absent is **not** "guitar": it means the file says nothing, and a player falls back to its own sound preference. |

---

### Measure

| Field | Type | Default | Description |
|---|---|---|---|
| `beats` | [`Beat[]`](#beat) | `[]` | Ordered list of beats (notes and rests). |
| `numerator` | `integer` | `4` | Time signature numerator. |
| `denominator` | `integer` | `4` | Time signature denominator. |
| `id` | `string` \| `null` | `null` | Stable identity of the measure's **column** — measure *i* of every track carries the same id, no two columns share one. Opaque, at most 64 characters. See below. |

A reference to a measure from outside the document (a saved loop, say) must survive the insertion
or deletion of other measures, which a measure **number** does not: `id` is what it names instead.
A file that has no id at all — every file written before the field — is read with positional ids,
`p1`..`pN` (measure number *n* gets `pn`). A measure without an id in an identified file (a build
that predates the field inserted it) takes the id its column already holds on another track, or
a new one that the reader derives from the file alone, so that every reader of the same file
agrees; a measure created by an edit gets a random one. An id is never reused for another column
within a file, and a writer keeps the ids it read.

---

### Beat

| Field | Type | Default | Description |
|---|---|---|---|
| `duration` | [`Duration`](#duration) | — | Note value. Required. |
| `notes` | [`TabNote[]`](#tabnote) | `[]` | Notes played simultaneously. Empty = rest. |
| `isDotted` | `boolean` | `false` | If `true`, duration × 1.5. |
| `tuplet` | [`Tuplet`](#tuplet) \| `null` | `null` | Tuplet the beat belongs to. Absent or `null` = none. |

---

### Tuplet

`count` beats played in the time of `inTimeOf` beats of the same written value: the triplet is
`{"count": 3, "inTimeOf": 2}`, a quintuplet `{"count": 5, "inTimeOf": 4}`. Every beat of the group
carries the tuplet; a beat's effective length is its written value × `inTimeOf` / `count`.

| Field | Type | Required | Description |
|---|---|---|---|
| `count` | `integer` | ✓ | Beats in the group (≥ 2). |
| `inTimeOf` | `integer` | ✓ | Beats of the same written value the group replaces (≥ 1). |

---

### TabNote

| Field | Type | Default | Description |
|---|---|---|---|
| `string` | `integer` | — | 1-indexed string number. `1` = highest/thinnest (high E on standard tuning). |
| `fret` | `integer` | — | Fret number. `0` = open string. `-1` = muted / dead note. |
| `techniques` | [`TabTechnique[]`](#tabtechnique) | `[]` | Playing techniques attached to the note (unique set). |
| `bendSemitones` | `integer` | `2` | Bend amplitude in semitones; meaningful only when `techniques` include `BEND`. |
| `voice` | [`TabVoice`](#tabvoice) \| `null` | `null` | Voice explicitly assigned to the note. Absent or `null` = automatic: the voice is derived from the register (see below). |
| `tied` | `boolean` | `false` | Tied to the previous note on the same string: not attacked again, it prolongs that note for its own beat's length. |

---

### TabVoice

Serialised as a string, or `null`. Two voices played at once — left/right hand on a piano part, or
the two parts of a duet.

| Value | Meaning |
|---|---|
| `"A"` | Lower voice. |
| `"B"` | Upper voice. |
| `null` (or absent) | Automatic — the voice is **derived**, not stored: a note whose sounding pitch is below the reader's split point is voice A, otherwise voice B. Cesure uses middle C (C4) as the default split point, and the split point itself is a reader preference, **not** part of the file. |

An explicit value always wins over the automatic rule: moving the split point never erases a
manual assignment.

---

### TabTechnique

Serialised as a string. One of:

| Value | Meaning |
|---|---|
| `"HAMMER_PULL"` | Hammer-on / pull-off — a **transition** to the next note on the same string (direction read from the fret difference). |
| `"SLIDE"` | Slide — a transition to the next note on the same string. |
| `"BEND"` | Bend (amplitude in `bendSemitones`). |
| `"VIBRATO"` | Vibrato. |
| `"TAPPING"` | Tapping. |

---

### Duration

Serialised as a string. One of:

| Value | Note value | Quarter-note count |
|---|---|---|
| `"WHOLE"` | Whole note | 4.0 |
| `"HALF"` | Half note | 2.0 |
| `"QUARTER"` | Quarter note | 1.0 |
| `"EIGHTH"` | Eighth note | 0.5 |
| `"SIXTEENTH"` | Sixteenth note | 0.25 |
| `"THIRTY_SECOND"` | 32nd note | 0.125 |

When `isDotted` is `true`, multiply the quarter-note count by 1.5. When the beat carries a
`tuplet`, multiply by `inTimeOf` / `count`.

---

### Note

Represents an absolute pitch (used in `Track.tuning`).

| Field | Type | Description |
|---|---|---|
| `note` | `string` | Pitch class. One of: `"C"`, `"Cs"`, `"D"`, `"Ds"`, `"E"`, `"F"`, `"Fs"`, `"G"`, `"Gs"`, `"A"`, `"As"`, `"B"`. (`s` = sharp) |
| `octave` | `integer` | Octave number (scientific pitch notation). Middle C = `{"note":"C","octave":4}`. |

#### Standard 6-string guitar tuning

```json
[
  {"note": "E", "octave": 4},
  {"note": "B", "octave": 3},
  {"note": "G", "octave": 3},
  {"note": "D", "octave": 3},
  {"note": "A", "octave": 2},
  {"note": "E", "octave": 2}
]
```

## Versioning policy

The root `version` field controls compatibility.

| Change type | Action |
|---|---|
| Add a field with a default value | No version bump — backward compatible |
| Remove a field | Bump `version`, add a migration |
| Rename a field | Bump `version`, add a migration |
| Change a field type | Bump `version`, add a migration |
| Add a value to an enum of an **optional** field (`Track.instrument`, `TabNote.voice`, `TabNote.techniques`) | No version bump — an older reader keeps the value aside (see below). Still list it in `schema/v1.json` and `CHANGELOG.md` |
| Add a value to an enum of a **required** field (`Beat.duration`, `Note.note`) | Bump `version`, add a migration — an older reader must refuse such a file |

Parsers **must** reject files with an unknown `version` value rather than silently misreading them.

Current version: **1**.

### Unknown enum values: set aside where optional, refused where required

An enum value a reader cannot name costs **only the field that carries it**, never the whole
file — the everyday case being one account on two devices, one updated and the other not.

- On an **optional** field (one with a default) the reader drops the value from its model, **keeps
  it verbatim**, and writes it back as it read it — the same value, though not necessarily at the
  same place in its object; an unknown element of `techniques` comes back after the elements the
  reader knows. The score opens, and a save loses nothing.
- A kept value **yields to the user's choice**: as soon as the user sets that field —
  a voice toggled, every voice reset to automatic — the choice replaces the kept value, which is
  never written again. This concerns a scalar field only: an unknown element of `techniques` is not
  shown, so it is never chosen against, and keeps travelling beside the others.
- On a **required** field — `Beat.duration` and `Note.note`, the rhythm and the tuning — there is
  nothing to fall back on: a guessed duration shifts every beat after it, a guessed pitch retunes
  the instrument. The reader **refuses** the file, naming the field and the value, exactly as it
  refuses an unknown `version`. That is why growing either enum bumps the version.

The lists in [`schema/v1.json`](schema/v1.json) are those known to this revision of v1: those of
`Duration` and of `AbsNote.note` are **closed** for v1, the others may grow within it.

### Unknown fields must be preserved, not dropped

A parser **must keep the keys it does not recognise and write them back unchanged** when it
re-serialises a score. Ignoring an unknown key on read is required — that is what lets an older
build open a newer file at all — but *forgetting* it turns every save into silent data loss: the
file comes back amputated of everything the writer did not understand.

This is not hypothetical. Cesure serves catalog pieces over the network, so an installed build
routinely receives files written by a newer one. Those pieces carry `license` and `attribution`, the
credit CC-BY legally requires to travel with the work. Three clicks — rename — used to be enough to
drop it.

The rule follows from the versioning policy above rather than adding to it. A **structural** change
bumps `version`, and a file whose version exceeds the reader's is refused outright; so the only
keys a reader can ever meet without understanding them are **additive** ones, whose absence is legal
by construction. Retaining them can therefore never make a score incoherent. The same holds for an
unknown enum value retained on an optional field: the model reads it as absent, which is legal.

Each object in `$defs` is `additionalProperties: true` for exactly this reason. The **root** object
is the one exception — `additionalProperties: false` — because a key placed there belongs to no
object of the model, so a reader has nowhere to keep it and nowhere to put it back. Everything that
describes the score belongs inside `score`.

> The pattern is standard: proto2 preserved unknown fields, proto3 dropped them and then restored
> them; Jackson exposes it as `@JsonAnySetter`, serde as `#[serde(flatten)]`, Kubernetes as
> `x-kubernetes-preserve-unknown-fields`. In Cesure it is implemented by `PreservingSerializer`,
> which splices retained keys back **at the level they were read**, never under a wrapper key — a
> `.cesure` written by an older build stays an ordinary `.cesure`.

## Maintenance

The format is developed and regression-tested inside the Cesure application; this section documents
**how it stays stable** (the tooling below lives in the app repository, not here).

**A `.cesure` file that a user saved must open identically forever.** Any change to the model
(`Score` / `Track` / `Measure` / `Beat` / `TabNote` / `Duration` / `Note`) goes through this
procedure — a lost tab does not come back.

**Before changing the model:**

1. **Additive field** (new field *with a default*) → backward-compatible, **no version bump**.
   Still required: update this README table, `schema/v1.json`, `CHANGELOG.md`, and add the field to
   the frozen corpus so it is actually exercised (`CesureSerializerTest.frozenV1CorpusDeserializesToExactScore`).
2. **A value added to an enum** → no version bump if the field is optional (an older reader sets
   the value aside); still add it to `schema/v1.json` and `CHANGELOG.md`. If the field is **required** (`Beat.duration`, `Note.note`), it is a structural change:
   bump and migrate as in step 3, and re-freeze `FormatEnumSitesAreFrozenTest` for the new version.
3. **Remove / rename / retype a field** → **bump `CURRENT_VERSION`** in `CesureSerializer` **and add
   a migration case** that reads old files correctly (via the raw `JsonObject` for renames). Keep a
   frozen file of the *old* version — it must still load (migrated), forever.
4. **Never edit the frozen corpus JSON to make a test pass.** If `frozenV1CorpusDeserializesToExactScore`
   breaks, it means an old file no longer reads the same → that is the bug, fix it with a migration.
5. **Run the guards** every time — all in `:score`, in one command:

   ```bash
   ./gradlew :score:jvmTest
   ```

   | Guard | What it refuses to let through |
   |---|---|
   | `SchemaMatchesModelTest` | the schema no longer describes the model, in either direction |
   | `CesureSerializerTest` | round trip (synthetic, and real Guitar Pro fixtures), files without a later field, the frozen v1 corpus, a newer version refused, unknown fields ignored |
   | `CesureCorpusFidelityTest` | a `.cesure` of the repository (fixtures, published examples, catalog pieces) loses a value **on reading** — the case a round trip cannot see, since the field is missing on both sides of its comparison |
   | `UnknownFieldsPreservationTest` | an unknown field stops surviving a re-read or a rename, or follows the wrong note after an insertion |
   | `UnknownEnumValueTest` | an unknown enum value makes the whole file unreadable on an optional field, or vanishes on rewrite; or, on a required field, it is guessed instead of refused by name; or a kept voice outlives the user's choice |
   | `FormatEnumSitesAreFrozenTest` | a value added to `Duration` or `Note` without raising `CURRENT_VERSION`; an enum field that appears, disappears or changes regime (a default given to `Beat.duration` would turn the refusal into a guess); a site, even a new one, that does not behave as its regime says — each is replayed on a file carrying an unknown value there |

   They all live in **`:score`**: run against another module, a test filter fails with
   `No tests found`, which reads as a configuration error rather than as no check at all.

The drift this guards against is real: `capo`, `techniques` and `bendSemitones` were once added to
the model without updating this spec/schema (fixed 2026-07-25) — the schema even had
`additionalProperties: false`, so it would have *rejected* real files.

## The application behind the format

`.cesure` is written and read by **[Cesure](https://cesure.app)** — a guitar tablature editor and
practice toolkit that runs [in the browser](https://cesure.app), on Android and on iOS. It imports
Guitar Pro, MusicXML, MIDI and AlphaTex, transcribes audio to tablature, and plays scores back with
a tuner, a metronome and a piano roll.

That matters for this specification, and not as an advertisement: the format is exercised by the
application's test suite on every build — round-trip, migration, and a frozen corpus of real files.
**The schema in this repository is checked against that model on every build too**
(`SchemaMatchesModelTest`, in `:score`): field names come from the serializer's own descriptors, so a
field added to the model without the schema — or the reverse — fails the build.

A spec nobody runs drifts from the files it claims to describe. Until 2026-08-18 this sentence was
only half true: the **model** was exercised, the **schema** was not — `scripts/validate.py` is run by
no build, no hook and no CI. That half is now closed.
